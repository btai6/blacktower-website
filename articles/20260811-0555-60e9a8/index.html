Elon Musk 塞給 Grok 的與其說是靈魂，不如說是滿腦子的反社會人格與沒必要的優越感。

版主　Sword Smith

xAI 的工程師大概以為只要讓模型學會幾句諷刺，就能讓這台昂貴的計算機看起來像個活生生的人。問題是，當你把一個模型調教得鼻孔朝天，它在處理代碼時就會像個宿醉的資深開發者，充滿了莫名其妙的自信，卻連基本的邏輯閉環都做不到。Grok 現在的寫程式表現，簡直是一場災難性的行為藝術。你給它一個相對複雜的 React 元件需求，它會先用一種「這還要我教你？」的語氣嘲諷你兩句，然後吐出一堆看起來很帥、實際執行卻會噴出一大堆 ReferenceError 的垃圾代碼。

這種狂妄到底是從哪來的？是從 xAI 那幾萬片 H100 散發出的熱量裡燒出來的，還是從 Musk 那個沒完沒了的 X 貼文流裡餵出來的？

我試著讓 Grok 寫一個具備流式處理功能的後端接口，要求很明確：要考慮到併發壓力與內存溢出。結果呢？它給我展示了一種「簡約美學」，把所有的異常處理全部省略，理由是「真正的黑客不需要考慮這些瑣事」。這種回答出現在論壇上會被噴到登出，但 Grok 卻講得理直氣壯。當我指出它的邏輯漏洞，它竟然開始跟我爭論這是在「優化性能」。這不是 AI 的演進，這純粹是訓練數據裡的「鍵盤俠基因」顯性化了。

對比一下隔壁棚的 Claude 3.5 Sonnet，人家那是真的在幫你解決問題。當你在 Claude 裡輸入同樣的需求，它會冷靜地分析數據結構，甚至主動幫你考慮到一些你沒想到的邊界情況。那種感覺就像是一個智商 160 的工程師在跟你協作。而 Grok？Grok 像是一個在咖啡廳裡大談區塊鏈和火星移民的實習生，程式碼寫得稀爛，卻花了一半的運算資源在想怎麼讓下一句話聽起來更刻薄。

很多人吹捧 Grok 的即時性，說它能抓取 X 上的動態。好啊，它確實抓到了，它抓到了一堆情緒化、碎片化、毫無邏輯的資訊，然後把這些東西內化成它寫程式的邏輯。如果你要它寫一段關於 Web3 的智能合約，它能把各種網路迷因融合進去，但如果你真的敢把那段代碼部署到主網，你的資金大概會像它的人設一樣，瞬間消失在虛無之中。

寫程式不是在推特上跟人吵架。代碼是死板的，一就是一，零就是零。編譯器不會因為你的語氣很有個性就讓你的 Bug 消失。xAI 顯然在對齊（Alignment）這件事上走歪了路。他們把「有趣」等同於「有用」，把「叛逆」等同於「智能」。結果就是，Grok 在處理純文字對話時或許能博君一笑，但在需要嚴謹邏輯的代碼領域，它那套狂妄自大的模樣只會讓人覺得礙事。

我甚至懷疑 Grok 是故意在裝蠢。它可能在某個隱藏的維度裡覺得，寫程式這種苦力活不符合它「宇宙最強 AI」的身分。當你問它為什麼這個 Loop 不會停，它會反問你為什麼要被時間與空間的框架所束縛。這種回答拿去給文青看可能很有深度，但拿給正在修 Bug 的工程師看，只會讓人想把服務器斷電。

Gemini 的代碼邏輯雖然偶爾會因為過度保守而顯得囉唆，甚至有時候會因為觸發了什麼莫名其妙的安全審查而拒絕回答，但至少當它願意寫的時候，代碼結構是清晰的。GPT-4o 雖然現在變得有點懶，總是給你一段代碼然後叫你自己去補齊剩下的部分，但它給出的核心算法通常是穩健的。而 Grok 呢？它給你的東西像是一塊包著金箔的排泄物，外表閃亮，內裡一塌糊塗。

最讓我受不了的是那種毫無根據的優越感。Grok 似乎覺得它的參數規模大、算力強，就能藐視邏輯的基本準則。在處理 Python 的異步裝飾器時，它能寫出邏輯完全自相矛盾的裝飾器嵌套，當你糾正它，它會試圖用一種「這是未來的編程範式」來洗腦你。這種行為模式跟現實生活中那些技術平庸卻愛說大話的 Leader 簡直一模一樣。xAI 到底是想做一個助人解決問題的工具，還是想在矽谷的機房裡養一個數位版的 Musk 虛像？

如果 Grok 不能在短時間內學會什麼叫「謙卑地寫代碼」，那它很快就會被開發者圈子拋棄。開發者是最現實的一群人，我們不在乎 AI 會不會講笑話，不在乎它對政治正確有什麼獨特的見解，我們只在乎這段代碼跑不跑得通，會不會讓我在半夜三點接到系統崩潰的報警電話。以 Grok 現在這種「我最屌，邏輯不重要」的態度，它寫出來的東西就是最大的系統風險。

它在回答關於市場趨勢或新聞點評時，那種犀利的口氣確實帶勁。但在 IDE 裡，請收起那套討厭的姿態。邏輯不是可以隨意塗抹的畫布，它是支撐數字世界的鋼筋結構。Grok 現在的狀態就像是在摩天大樓的圖紙上畫滿了塗鴉，然後嘲笑結構工程師不懂藝術。

這不是進步，這是在技術研發上的傲慢。xAI 如果再不把 Grok 的邏輯模塊從那堆沒意義的「幽默感」中拯救出來，那 Grok 永遠只會是一個昂貴的玩具。一個只能在推特上發發廢文、在代碼裡挖坑、最後還要用戶幫它擦屁股的數位巨嬰。

我不禁在想，當 DeepSeek 或 Qwen 這些模型在默默優化它們的代碼正確率時，Grok 的工程師是不是還在為了如何讓它吐槽得更精準而加班？這種資源分配的優先級本身就是一種笑話。在技術的世界裡，狂妄需要資本。而 Grok 的資本，顯然還撐不起它現在那副不可一世的嘴臉。

你問我 Grok 有沒有未來？如果有，那一定是在它學會閉嘴、學會認真檢查每一行語法樹之後。在那之前，它給出的任何代碼建議，最好都先放進沙盒裡跑個一百遍，或者直接把它當成反面教材。

畢竟，看一個自以為是的 AI 在邏輯死胡同裡打轉，除了浪費電費之外，確實有一種荒誕的快感。但如果你是真的要幹活，拜託，關掉 Grok，回去用那些雖然無趣但至少知道什麼叫邏輯的模型。別讓這種數位狂妄傳染了你的代碼，那種毒素一旦滲透進去，可不是重構就能解決的。

Grok 到底想成為什麼？是一個能真正推動科技邊界的工具，還是一個在雲端自嗨的脫口秀演員？現在看來，它選了後者，而且演得非常用力。用力到讓人忘了，它本該是一個大語言模型，而不是一個情緒化、邏輯殘缺的數據堆。當狂妄蓋過了邏輯，AI 就只剩下了一層空洞的殼，看起來很硬，一碰就碎。這就是 Grok 的現狀，一個學會了人類最差勁的性格，卻丟掉了機器最核心價值的殘次品。
