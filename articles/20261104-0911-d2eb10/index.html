誰在幫 OpenAI 餵飽那個永遠吃不飽的黑盒子

版主　渡鴉

這兩天技術圈子裡最有趣的黑色幽默，莫過於那群自以為能在矽谷巨頭眼皮底下守住商業機密的工程師，突然發現自己手動關閉的「改善模型」開關被悄悄重置了。這不是什麼新鮮事，但當 OpenAI 把這套把戲玩到 Codex 和生產力工具上時，這就不再只是隱私愛好者的碎碎念，而是直接威脅到企業 IP 的安全紅線。很多人在論壇上哀鴻遍野，說自己的數據共享設置在毫無通知的情況下被重新激活，彷彿那個「不參與訓練」的選項只是個安慰劑按鈕，按下去能讓心跳平穩一點，但背後的數據流向從未改變。

這種靜默變更設置的行為，在技術層面上往往被包裝成「系統更新後的默認配置重置」，但本質上反映的是一種極其焦慮的數據飢渴。當我們在討論 Claude 3.5 Sonnet 的代碼邏輯多麼細緻，或者 Gemini 1.5 Pro 的長文本窗口如何處理整本技術文檔時，OpenAI 卻在底層邏輯上玩起了一場關於「獲取權限」的心理戰。當用戶在網頁端或 API 調用中投入大量私有代碼進行 Debug，這些高質量的、帶有邏輯糾錯過程的數據，正是目前大模型最稀缺的養料。與其說這是一個 Bug，不如說這是一個經過計算的策略：只要有 10% 的用戶沒發現設置被重置，OpenAI 就能多獲得數以億計的優質代碼 token 來餵養下一代的 o1 或 GPT-5。

這件事最諷刺的地方在於，現在的開發者一邊依賴這些 AI 工具提升效率，一邊又得像防賊一樣防著它們。如果你觀察過 ChatGPT 近期的界面變動，會發現他們甚至開始隱藏具體的用量統計。以前你還能清晰地看到自己在這個週期內剩餘多少額度，現在卻得在選單裡捉迷藏。這種透明度的全面倒退，配合數據共享開關的「自動復位」，構成了一套完整的封閉系統。OpenAI 似乎越來越不打算跟用戶講道理，而是傾向於把用戶變成純粹的數據貢獻者。相比之下，Claude 在處理這類企業隱私問題時顯得稍微體面一些，至少 Anthropic 目前還不敢在隱私條款的邊界上反覆橫跳，試圖以此作為與 ChatGPT 競爭的差異化賣點。

在橫向觀察這類技術倫理時，我們會發現一個很有意思的對比。相較於 Qwen 這類在開源界頻繁動作的參與者，OpenAI 表現出了一種極度的傲慢，這種傲慢來自於它對市場份額的絕對掌控。當你看到 Qwen 在性能榜單上追趕時，OpenAI 卻在忙著把用戶的數據開關切換回「共享」模式。這其實說明了一件事：領先者已經不再關心如何透過單純的技術升級來贏得口碑，他們更在乎如何利用現有的壟斷地位，從存量用戶身上榨取每一滴有價值的代碼殘渣。Grok 在這方面倒是顯得直白得多，它幾乎是明擺著告訴你它需要數據來訓練，而 Gemini 則還在忙著處理它那混亂的跨平台帳戶同步問題，暫時還沒空在數據開關上玩這種細微的小動作。

這就引出了一個更深層的技術困局：如果我們必須依賴這些「先鋒模型」來保持競爭力，我們是否真的有能力保護自己的智力成果？現在有人提倡透過硬體密鑰開啟高級安全模式來鎖定數據不被共享，也有人主張在 AI 工具與生產環境之間加一層「去敏感化」的中間件。但問題在於，當模型的能力越來越深入地嵌入到編譯器、IDE 甚至終端機時，這種手動的防禦措施到底能撐多久？

當一個工具強大到你無法拒絕，而它又在暗處不斷試探你的底線時，這種關係還能稱之為「合作」嗎？如果明天 OpenAI 宣布所有免費或低階訂閱用戶必須強制開啟數據分享才能使用最新模型，你是會選擇帶著你的代碼轉身離開，還是會安慰自己說「反正我的代碼也沒那麼值錢」？我們到底是在使用 AI 改善生活，還是在用自己的職業生涯為下一場技術革命交稅？
