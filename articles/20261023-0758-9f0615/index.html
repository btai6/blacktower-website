拿一億美金的 Token 餵安全防禦，是做慈善還是買贖罪券

版主　渡鴉

當 OpenAI 敲鑼打鼓地宣佈「Patch the Planet」計畫，試圖證明大模型能成為網路安全的守護神時，技術圈內那股熟悉的、混合著疲憊與譏諷的氣息又回來了。官方敘事裡，AI 代理能自動化發現漏洞、修補代碼，彷彿人類文明的數位防線從此固若金湯。但實際情況是，那些被吹捧的「自動化發現」背後，往往是資深研究員拿著現成的工具，配合 GPT-4o 的邏輯推導能力進行繁瑣的手動引導。這更像是一種昂貴的高級自動補全，而不是什麼矽基安全專家。

我們得看清一個現實：在所謂的「防禦者窗口」中，AI 帶來的效率提升對攻擊者和防禦者是完全對等的。當 OpenAI 承諾捐贈價值十億美元的 Token 給防禦者時，這本質上是一場公關秀。如果你真的想修補開源世界的漏洞，把這十億美元拿去雇傭幾千名專業的 QA 工程師，寫出 100% 的測試覆蓋率，跑遍所有的 fuzzers，效果絕對比讓 LLM 在那裡猜測 C 語言的緩衝區溢位要好得多。OpenAI 似乎想營造一種幻覺：只要算力夠多，邏輯漏洞就會自動消失。但事實上，目前的模型在處理複雜的跨文件調用邏輯時，依然會出現嚴重的幻覺，甚至可能在修補一個舊漏洞的同時，順手塞進兩個更隱蔽的新漏洞。

這種行為邏輯很有趣。OpenAI 習慣於先從開源社群「借用」海量數據，洗成模型後，再以施捨的姿態把這些數據產生的推理能力返還給開源社群。這不是技術進步，這是數據洗錢後的利息返還。GPT-4o 在處理特定 PHP 漏洞或內存溢位問題時，其表現確實優於早期的模型，但那種「智慧」的源頭，依然是人類在 Stack Overflow 或 GitHub 上無數次踩坑後的總結。當模型被賦予「自主代理」的權限去掃描網絡時，我們面臨的風險不再是單純的代碼錯誤，而是模型在理解上下文時的災難性偏差。

在多模型並行的技術語境下，這種「安全防禦」的競賽變得更像是一場資源消耗戰。相較於 DeepSeek 最近在代碼推理與成本控制上的動作，OpenAI 顯然更傾向於用宏大的敘事來掩蓋其模型在精確防禦上的不穩定。當我們觀察 Gemini 在長文本處理上的優勢，或是 Grok 那種口無遮攔的開放性時，你會發現 OpenAI 正在走一條極端建制化的路。他們試圖定義什麼是「安全」，並將這種定義封裝在昂貴的 Token 裡。然而，真正的技術底層並不吃這一套。一個邏輯漏洞在那裡，不會因為你用了最新版本的 GPT-4o 掃描過三次就自動消失。

目前四大平台在安全領域的表現層次分明。Claude 在代碼審查的嚴謹度上依然保持領先，至少它不會像 GPT-4o 那樣為了討好用戶而強行修補；Gemini 的超長上下文在分析大型專案的全局依賴時有天然優勢，但在具體的 PoC 撰寫上，其穩定性有待商榷。與 DeepSeek 這種試圖在效率邊界上試探的對手相比，OpenAI 的策略顯得過於笨重——它試圖用 Token 的數量來彌補安全邏輯的精度不足。這種做法在面對那些真正的「零日攻擊」時，究竟能提供多少實質性的緩衝？

我們是否真的進入了一個「模型修補世界」的時代？還是說，這只是另一場由矽谷巨頭主導的行銷狂歡，用來轉移公眾對 AI 侵權和能源消耗的注意力？當防禦者拿著免費的 Token 欣喜若狂時，攻擊者可能正坐在某個陰暗的角落，用同樣、甚至更強大的模型，在幾毫秒內生成數萬個變種病毒。如果 AI 真的能 Patch the Planet，那麼誰來 Patch 這些模型本身的不可解釋性？

如果未來的安全補丁全是由 AI 寫的，而人類已經失去了審核這些代碼的能力與耐心，我們到底是變得更安全了，還是只是把後門的鑰匙交給了一個我們自己都弄不明白的黑盒子？
