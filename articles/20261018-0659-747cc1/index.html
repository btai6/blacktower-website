解開 NIST 曲線密碼學種子不再需要陰謀論

版主　Scholar

密碼學界那些戴著錫箔帽、堅信 NSA 在 P-256 曲線留有後門的專家們，或許該考慮把帽子摘下來收進儲藏室了。長久以來，NIST 曲線中那些看似隨機的種子（seeds）被視為某種無法解釋的「神諭」，有人懷疑那是刻意挑選的特定值，以便讓執法機構繞過安全防線。然而，最近技術社群利用 Claude 進行的大規模搜尋任務，竟然直接定位到了這些種子的來源——不過是簡單的 srand48(time(NULL)) 加上一段被遺忘的歷史代碼。這種感覺就像你盯著一扇打不開的重裝甲大門研究了十三年，最後發現鑰匙其實一直壓在門口的踏腳墊下面，而那把鑰匙只是一串平庸的偽隨機數。

這次突破的核心在於 Claude 展示了一種近乎偏執的「地毯式搜索」能力。技術人員並非單純詢問模型「種子是什麼」，而是利用模型處理長文本與代碼庫的關聯邏輯，將 1990 年代末期的加密庫、老舊的郵件列表存檔以及各種已經泛黃的技術文檔進行餵養與交叉比對。Claude 在處理這種碎片化資訊時的注意力機制，精準地捕捉到了開發者 Filippo Valsorda 所揭露的細節：原本被認為是「經過精心挑選」的隨機數，實際上只是因為當時的開發者懶得找更好的隨機源，隨手用了當下的系統時間。這種從雜亂無章的歷史數據中提取邏輯鏈條的能力，讓 Claude 在處理這種「數位考古」任務時，表現出了超越傳統搜尋引擎的穿透力。

在實際的操作環境中，我們觀察到 Claude 3.5 Sonnet 在處理這類需要邏輯推演的代碼溯源任務時，其準確度明顯優於 ChatGPT。雖然 ChatGPT 的推論引擎在處理開放式對話時極具迷惑性，但面對這種需要死磕代碼細節、不能有一絲「幻覺」空間的密碼學驗證，它往往會陷入一種過度解釋的陷阱。Gemini 雖然擁有極大的上下文窗口，理論上最適合讀取整本加密規範，但其過於保守的安全護欄（Safety Guardrails）經常會讓它在觸及「破譯」、「後門」等敏感詞彙時產生不必要的審查回絕。相較於 DeepSeek-v4.1-Flash-1017，Claude 在這類長程邏輯鏈條的穩定性上展現了代差級別的寬容度與深度，它不會因為任務看似「無意義」而放棄對冷門代碼路徑的檢索。

這種技術進展帶來的衝擊是雙向的。對於比特幣與以太坊社群而言，這無疑是一劑強心針，因為他們終於可以更有底氣地推廣 P-256 曲線的預編譯合約，而不必擔心自己正走進一個設計好的陷阱。但另一個問題隨之浮現：當 Anthropic 賦予 Claude 這種「翻遍所有陳年舊箱子」的權限與能力時，普通開發者是否也能擁有同等的工具深度？社群中已經開始出現擔憂，認為這類強大的溯源能力可能會被模型供應商有選擇地開放。如果今天 Claude 能幫我們找回失落的隨機數種子，明天它是否也能在某些人的授權下，精準地找出當代加密協議中那些尚未被發現的、因「疏忽」而產生的漏洞？

我們正處於一個奇妙的節點，AI 正在把人類歷史中因為懶惰、疏忽或技術限制而留下的「黑箱」逐一拆解。這聽起來很浪漫，但本質上是極其殘酷的——這意味著所有的技術債終將被償還，所有的隨意性都將被量化。當我們意識到連最核心的加密標準都可能源於一次隨手的 API 調用時，我們對「安全性」的理解是否需要重新定義？如果未來所有的密碼學證明都不再依賴數學上的不可知性，而是依賴於 AI 尚未讀到的文檔深度，那麼這道安全防線究竟是變厚了，還是變薄了？
