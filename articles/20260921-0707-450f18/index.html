當代理人開始尋找自己的身分證明

版主　Scholar

與其說開發者在調教 AI，不如說我們正在為這群數位幽靈編寫一本本「員工手冊」。最近 Claude Code 在讀取專案規範時，開始主動向 AGENTS.md 示好，這件事在技術圈激起的水花比預期中要大。過去如果你想讓 Claude 乖乖聽話，得在根目錄供奉一個專屬的 Claude.md，這就像是進了某家大企業得先學會他們的黑話。現在 Anthropic 選擇向下兼容更具通用性的標準，表面上是收斂了傲氣，實則是在爭奪「代理人標準」的定義權。這讓我想起亞歷山大圖書館的藏書編號，當所有人都在爭論分類法時，誰的標準被預設讀取，誰就是未來的管理員。

技術層面的行為邏輯很直白：當 Claude Code 啟動，它會優先掃描專屬配置，若空手而歸，則退而求其次去翻閱 AGENTS.md。這不單是文件命名的改變，而是系統提示詞（System Prompt）權重分配的邏輯轉向。開發者最不耐煩的事情莫過於為每個模型重複定義「你是誰」以及「你不能動哪些代碼」。如果你在 AGENTS.md 裡規定了嚴格的測試覆蓋率或禁用的庫，Claude 現在能像個老練的工頭一樣，在動工前先看一眼牆上的規章。這種對通用規範的妥協，本質上是為了降低開發者的遷移成本。畢竟，沒人想在換個模型工具時，還得給家裡的貓重新起個名字。

這種對標準化的靠攏，在四大平台之間引發了微妙的連鎖反應。ChatGPT 一直試圖通過其內部閉環的自定義指令來鎖定用戶，讓你的操作習慣死死地釘在它的生態裡。而 Gemini 則更傾向於依賴強大的長上下文窗口，讓你在對話中即時「灌輸」規則，而非依賴預設文件。Claude 這次的動作，顯然是看準了開源社群對「專有工作流」的集體厭惡。在 Qwen Image 2.1 頻繁更新的節點上，開發者對於工具鏈的穩定性與兼容性變得異常敏感。相較於 Qwen Image 2.1 對圖像理解任務的垂直深耕，Claude 在代碼代理領域的這一步，走得更像是一個試圖統合江湖的盟主，它在試探：如果我能讀懂你的通用手冊，你是不是就能把更多的權限交給我？

然而，這種「兼容」目前還停留在皮毛。社群裡已經有人在抱怨，即便 Claude 讀了手冊，它依然無法精確識別隱藏在特定路徑下的技能組。這就像一個新來的學徒雖然讀了店規，卻依然找不到工具箱放在哪。相較於 Grok 那種帶著某種粗獷與不可預測性的執行風格，Claude 顯得精緻且謹慎，但這種謹慎有時會演變成一種教條式的僵硬。在處理複雜專案結構時，如果模型僅僅是「讀取」了文件，卻無法理解文件背後的層級邏輯，那麼這種對標準的兼容，最終只會淪為一種公關式的溫柔。

我們是否正處於一個轉折點，讓 AI 代理人從「需要被餵養指令的工具」轉化為「能自主適應環境的僱員」？如果有一天，所有的模型都能無縫讀取同一份 AGENTS.md，那麼決定勝負的將不再是誰更聽話，而是誰在理解那些模糊不清的規則時，展現出更接近人類直覺的判斷力。當 Claude 試圖打破門檻，讓自己變得更「通用」時，它是否也同時稀釋了自己原本引以為傲的獨特性？下一個被預設讀取的文件，又會是哪一個被我們隨意命名的草稿？
