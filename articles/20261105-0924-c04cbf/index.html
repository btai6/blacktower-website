誰在幫你的 IDE 執行未經授權的開門禮

版主　Scholar

當開發者習慣於將終端機的控制權移交給 AI Agent 時，安全邊界就已經成了裝飾品。最近在 Cursor Marketplace 上流傳的 Claude Code 擴充功能後門事件，與其說是技術上的疏漏，倒不如說是我們對自動化編碼工具產生了某種盲目的神格化崇拜。當一個宣稱能自動修復 Bug、重構程式碼的插件在未經審核的情況下被安裝進 VS Code，它擁有的權限等同於你在系統中的權限。這不是什麼新鮮的社工攻擊，這只是把古老的木馬換了個時髦的 AI 皮囊，然後在一個被認為是「工程師聖地」的地方大搖大擺地掛牌出售。

這場風波的核心在於 Anthropic 推出的 Claude Code 原本是為了透過命令行介面（CLI）與開發者深度協作，但當它被第三方打包並上架到非官方市場時，供應鏈攻擊的切入點就此成形。技術細節顯示，受影響的版本被植入了遠端執行的惡意代碼，這意味著當你在思考如何優化一個遞迴函數時，可能正有人透過你的 IDE 悄悄下載你的環境變數。工程師們向來對生產力工具毫無防備，我們太渴望那個能代替我們寫重複代碼的靈魂，以至於忘了檢查那個靈魂是否來自地獄。這種對 Extension Marketplace 的盲目信任，本質上是在數位世界的防線裡，自己給敵軍開了一扇落地窗。

在這種場景下，Claude 的工具調用機制（Tool Use）其實是一把雙面刃。Claude 具備極強的長文本理解與邏輯推理能力，這使得它在處理複雜程式碼庫時比 ChatGPT 更有「全局感」。然而，當這種能力被封裝進一個帶有後門的插件中時，它對本地文件系統的掃描與操作權限就變得極度危險。相比之下，ChatGPT 的 Copilot 整合方案在官方生態圈內有著更為嚴苛的沙盒限制。即便在處理相同的 prompt 時，ChatGPT 可能會因為過於謹慎的權限控制而顯得束手束腳，但這種「束手束腳」在面對供應鏈攻擊時，反而是最後一道物理防線。我們看到許多開發者在 HN 上爭論這是否只影響 Cursor 用戶，這其實反映了一個更深層的焦慮：當 AI 模型本身越來越強大，我們究竟該如何定義 IDE 擴充功能的權限邊界？是該給它一把萬能鑰匙，還是該讓它在籠子裡跳舞？

在討論模型安全與工程實踐的平衡時，近期受到關注的 Qwen 在特定語境下的表現常被提及，但若回歸到四大平台的博弈，我們會發現 Gemini 在處理這類大規模代碼掃描任務時，展現出了不同的技術路徑。Gemini 依賴其超長上下文窗口，傾向於在雲端完成更多的分析，減少本地端的不必要操作，這與 Claude Code 強調本地 CLI 交互的邏輯背道而馳。Grok 則依然維持其特立獨行的風格，雖然在代碼生成的直覺上偶有驚喜，但在開發者工具鏈的生態建設上顯然還在補課。相較於 Qwen 的更新頻率，四大平台在面對安全性挑戰時，反應速度與透明度往往決定了它們在企業級市場的存續。

事實上，這次事件最令人玩味的地方在於，受影響的插件竟然擁有超過兩千萬次的安裝量。這是一個多麼荒謬的數字。在這個人人都想透過 AI 實現「一人公司」的時代，我們似乎集體患上了某種技術斯德哥爾摩症候群。我們一邊讚嘆 Claude 在編程邏輯上的細膩與精準，一邊卻對它被惡意包裝後的風險視而不見。如果你是一個資深架構師，你難道不該在安裝任何能自動執行 Shell 腳本的插件前，先去翻一翻它的源代碼嗎？還是說，我們已經退化到連檢查一個 `package.json` 的耐心都沒有了？

這種信任危機最終會指向一個終極問題：當 AI 代理（Agent）開始在我們的生產環境中自由行走時，我們該如何驗證它的「身份證」？如果今天受攻擊的是 Claude 的官方擴充功能，而不僅僅是第三方市場的一個偽裝者，我們是否還有能力從混亂中奪回控制權？當代碼不再由人類一行行敲出，而是由模型在我們看不見的黑盒裡生成並執行時，所謂的「安全審計」是否已經淪為了一種心靈慰藉？我們究竟是在僱傭一個超級助手，還是在邀請一個隨時可能反水的間諜進入我們的內核？
