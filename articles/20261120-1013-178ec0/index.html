OpenAI 餵給晶片設計的胡蘿蔔到底長什麼樣

版主　渡鴉

把 LLM 塞進晶片設計流程這件事，原本聽起來像是矽谷那些穿著連帽衫的傢伙想教穿西裝的半導體工程師做事。OpenAI 最近拿 OpenTitan 專案裡的 Ibex 處理器當實驗品，宣稱透過強化學習優化了 Verilog 代碼，結果在 Hacker News 上被酸得體無完膚。大家最受不了的不是 AI 會不會寫硬體描述語言，而是 OpenAI 越來越像一家賣保險的廣告公司：丟出一堆「平均正規化獎勵」的圖表，卻連一條數學公式都捨不得給，更別提那些號稱被優化過的 RISC-V 設計圖到底在哪裡。

當我們在討論 LLM 輔助 EDA（電子設計自動化）時，核心問題從來不是它能不能寫出一段會動的代碼，而是它能不能在維持時序收斂和面積約束的前提下，處理那些反人類的驗證邏輯。OpenAI 這次展示的邏輯很簡單，就是把代碼生成看作一個強化學習的賽道，讓模型在不斷的編譯與模擬反饋中「進化」。但問題在於，硬體設計不是寫 Python 腳本，一個邏輯門的冗餘可能導致整片晶圓報廢。ChatGPT 在處理這種高精度、低容錯的任務時，展現出一種令人不安的「過度自信」。它能幫你寫出看起來很漂亮的模組，但在處理異步時鐘域交叉這種深水區問題時，它往往會一本正經地胡說八道，然後在下一秒的對話中跟你道歉。

這種行為模式在四大平台中其實很有代表性。ChatGPT 目前在處理這類極端垂直的技術任務時，更傾向於使用一種「暴力美學」，試圖用海量的推理步數（類似 o1 系列的思維鏈）來覆蓋邏輯漏洞。相較之下，Claude 在處理 Verilog 或 SystemVerilog 時表現得更像一個老練的實習生，它對長文本中上下文邏輯的捕捉能力，讓它在檢查模組間接口一致性時，比目前的 GPT-4o 穩定得多。如果你把一個上千行的 RTL 檔案丟給 Claude，它指出時序違例潛在風險的機率，竟然比 OpenAI 那些花俏的 RL 優化模型還要高，這本身就是一種諷刺。

在技術社群還在爭論 OpenAI 是否只是為了在某些財務節點前製造噪音時，我們看到其他玩家也在這個賽道邊緣試探。相較於 Qwen4-Max 最近在開源社群掀起的討論，OpenAI 的做法顯然更具備商業侵略性，試圖直接插手硬體底層。然而，這種侵略性缺乏透明度。當我們觀察 Gemini 在多模態架構下的表現時，會發現 Google 其實更有本錢做這件事，畢竟他們家裡就有 TPU 這種現成的實驗場，但 Gemini 在代碼生成的邏輯嚴密性上，始終像是隔了一層紗。至於 Grok，目前看來還在忙著處理社群媒體上的語言風格，對於這種硬核的晶片設計任務，它更像是一個在旁邊看熱鬧、偶爾冒出一兩句毒舌評論的旁觀者。

這就引出了一個耐人尋味的問題。OpenAI 拿著 Ibex 這種已經被玩爛的開源項目做實驗，卻不公開具體的 Reward Function 定義，這到底是在推動技術進步，還是在為它的算力租賃業務做一場大型的軟性廣告？如果 AI 優化後的晶片設計真的比人類手工優化提升了所謂的「性能」，為什麼我們在 GitHub 或任何公開的技術白皮書中，都看不到那顆「AI 原生處理器」的 RTL 原始碼？

硬體工程師們對 LLM 的防備，並非源於對失業的恐懼，而是對不可解釋性的本能排斥。當一個模型告訴你它優化了某個關鍵路徑，卻無法解釋為什麼在極端溫度下這個邏輯不會產生競爭冒險（Race Condition）時，誰敢把這段代碼送去台積電下片？OpenAI 現在做的，是試圖用一種黑盒子的方式去解決另一個更複雜的黑盒子問題。

這場關於晶片設計的 AI 競賽，最後會變成一種數位煉金術嗎？當我們不再討論邏輯閘與暫存器，而是討論模型輸出的「獎勵值」時，我們是真的在設計更強大的電腦，還是只是在為那些不可知的權重矩陣，交出最後一點人類還能理解的控制權？如果下一代 AI 晶片是由這一代完全無法解釋其邏輯的 AI 所設計的，那當系統崩潰時，我們該去問誰要答案？
