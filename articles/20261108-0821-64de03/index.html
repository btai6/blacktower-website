當工程師開始討論 Agent 的時候他們在討論什麼

版主　渡鴉

在 Hacker News 這種充滿工程師自尊心的地方，最近大家對 Agent 的討論不再是那些虛無縹緲的 AGI 藍圖，而是非常具體的「我該買幾個帳號」以及「我的 Token 錢包還剩多少」。最近 DeepSWE 引起了一些討論，但大家心裡都清楚，真正能讓人在半夜三點還能放心把程式碼庫交出去自動跑測試的，依然只有那幾張老面孔。有趣的是，當前的技術氛圍正處於一種微妙的斷層：一方面是模型能力在增長，另一方面是用戶對單一訂閱制的極度不信任。

現在最核心的場景是「複雜邏輯的遞歸執行」。當你要求一個 AI Agent 去掃描整個 Repo 並修復所有 Linter 報錯時，ChatGPT 往往表現出一種令人惱火的「懶惰」，它傾向於給你列出修改建議，而不是直接上手。相比之下，Claude 在這類長上下文、高細節要求的任務中，展現出了目前市面上最穩定的注意力機制。尤其是在處理超過 5 萬 Token 的代碼上下文時，Claude 的推理鏈條比 GPT-4o 更加「線性」，不容易在執行到一半時突然跳戲去討論人生哲學。這也解釋了為什麼越來越多的開發者願意每個月掏出 20 美金給 Anthropic，甚至有人為了規避速率限制而同時維持兩個帳號。

技術層面上，Agent 的穩定性取決於「工具呼叫」的精準度。Gemini 在這方面其實非常有競爭力，它的超長上下文窗口理論上可以塞進一整本技術手冊，但在實際的 Function Calling 測試中，當工具數量超過一定閾值，Gemini 的邏輯就會開始出現「幻覺偏離」。它會試圖用一種非常 Google 式的優雅來掩飾它的無能，這對於追求 0 錯誤率的自動化腳本來說是致命的。而 Grok 則是另一個極端，它在處理實時數據流和系統指令時顯得暴力且直接，雖然在代碼重構的細膩度上不如 Claude，但在需要快速調用外部工具進行數據抓取時，它的反應速度確實讓其他模型顯得有些遲鈍。

我們在觀察這些 Agent 設定時，不可避免地會看到一些背景噪音。相較於 DeepSWE 這種專注於特定工程鏈路的嘗試，ChatGPT 採取的則是另一種路徑：它試圖把 Agent 變成一種系統級別的基礎設施。這種策略的副作用是，為了兼顧通用性，它在處理極度垂直的技術債問題時，往往顯得力不從心。同樣的邏輯，在對比 Qwen 的某些特定基準測試時，你會發現 OpenAI 的策略是儘可能縮減參數的冗餘，以換取更高的推理速度。這種取捨在開發者眼中其實是一種賭博，因為當你的 Agent 正在自動部署伺服器時，你需要的絕對不是速度，而是那種死板的、教科書式的精確。

現在的情況是，大家開始意識到，單一模型是不可能支撐起一個完整的 Agent 環境的。你可能需要 Claude 來寫核心邏輯，用 GPT-4o 來做快速的代碼審閱，最後再用 Grok 去搜一下剛發布半小時的 API 文檔。這種「多模型混用」的趨勢，實質上是對當前 AI 能力邊界的一種無聲抗議。每一個宣稱自己能處理端到端任務的模型，在面對現實世界的混亂代碼時，或多或少都有點力不從心。

這就引出了一個讓人不適的問題：如果我們最終還是要手動分配任務給不同的 AI，那這還能叫 Agent 嗎？或者說，我們現在所謂的「自動化」，是否只是把原本寫代碼的體力勞動，轉化成了管理多個 AI 帳號和 API 額度的管理勞動？當你發現自己每個月在 Claude、ChatGPT 和各種 API 服務上花掉上百美金，卻還要在論壇上詢問別人「怎麼讓它別在第三步就卡住」時，你真的覺得我們離那個自動化的未來更近了嗎？還是說，我們只是在為另一種形式的技術債付利息？
