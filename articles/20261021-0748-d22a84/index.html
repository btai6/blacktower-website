低成本推論神話與算力分配的隱形代價

版主　Trilobite

這幾天大家都在聊 DeepSeek 丟出來的那個推論框架，討論區裡瀰漫著一種矽谷實驗室要被降維打擊的末日感。那種單卡產出和營收比數據確實好看，看在創投眼裡簡直是把原本鑲金的推論成本直接打成了路邊的瓦礫。但我更感興趣的是，當所有人都在為「便宜」狂歡時，那幾個坐在頂峰的玩家，尤其是 Gemini，到底在盤算什麼樣的技術債。

Gemini 1.5 Pro 推出時，最讓人詬病也最讓人驚艷的就是那個動輒百萬級別的上下文視窗。在實際的 API 調用中，我們發現 Gemini 處理長文本的邏輯與其說是技術突破，不如說是對算力極度奢侈的揮霍。當你把一整本技術文檔丟進去，Gemini 的 Prefill 階段（預填充）速度極快，這背後依賴的是 Google 自家的 TPU 叢集與一套極其複雜的 KV Cache 管理機制。這套機制跟現在市面上強調「輕量、高速、低成本」的開源框架完全是兩條平行線。Google 從來沒想過要幫你省錢，它想的是如何在你還沒反應過來之前，就把幾十萬個 Token 的關聯性全部算完。

這種「算力換體驗」的暴力美學，在 Gemini 1.5 Flash 上表現得更露骨。很多人拿 Flash 跟各類開源小模型對標，覺得大家延遲差不多，但一旦進入多模態並發場景，差異就顯現出來了。Gemini 在處理影音串流輸入時，它的注意力分配機制並不是均等的。它會針對畫面變動劇烈的區格分配更多的計算資源，這導致了它的 Token 消耗極不穩定，但也確保了理解的精確度。這種動態資源調配，是那些追求恆定高吞吐量的框架目前還觸碰不到的邊界。

相較於 DeepSeek 在推論效率上的極致優化，Google 的做法顯得有些傲慢且笨重。Google 似乎認定了未來 AI 的基礎設施必然是中心化的、資源無限供應的黑盒。這就產生了一個有趣的技術斷層：一邊是試圖在有限的硬體上榨出最後一滴性能的民間高手，另一邊則是像 Google 這樣，把整個資料中心當成一個單一節點在操作的巨頭。Gemini 的 Function Calling 在處理超過 20 個工具調用時，成功率會出現明顯的震盪，這其實就是模型在過於廣泛的權重搜索中迷失了方向。它太強大了，以至於它在處理簡單任務時，依然帶著某種難以卸下的負載。

我們再看 ChatGPT 和 Claude。OpenAI 最近的動作明顯在往 O1 這種推理鏈方向走，這本質上是在增加單次輸出的計算深度，而非廣度。而 Anthropic 則是在對齊感與邏輯嚴密性上死磕。當我們把這些放在一起看，你會發現矽谷這幾家公司已經集體放棄了「降低推論門檻」這條路。他們更傾向於讓模型變得更貴、更難以私有化部署，以此來換取某種接近人類思考的「厚度」。

在這種語境下，所謂的高吞吐量、低延遲，反而變成了一種二線戰場的指標。Qwen 在某些基準測試中跑分驚人，但回到開發者的桌面，當你需要模型處理一個具有模糊語義的架構設計時，大家還是會乖乖回去刷 Gemini 或 GPT 的信用卡。這不是因為開源框架不好用，而是因為「效率」本身就是一種陷阱。當你優化了速度，你必然犧牲了權重中那些微小但致命的擾動，而那些擾動往往就是靈感的來源。

如果未來 AI 發展的終局是成本趨近於零，那麼 Google 現在投入數十億美元研發的 TPU 體系，究竟是在構築護城河，還是在給自己挖墳墓？當計算資源不再是稀缺財，模型本身的「性格」與「邏輯完整度」是否會取代「吞吐量」，成為衡量智力的唯一標準？或者說，我們現在追求的極致效能，其實只是在算力過剩時代到來前，一場集體的過度反應？
