當 Qwen3.8-27B 在某些討論區被吹捧成輕量化標竿時，OpenAI 卻在演示什麼叫「大象轉身後的滿地狼藉」。

如果說大型語言模型是矽谷這幾年供奉的神祇，那 ChatGPT 的帳戶安全機制就是神像腳下那塊鬆動的瓷磚。最近那個「點個連結就送出帳戶權限」的漏洞，其實挺有黑色幽默。一個宣稱能理解量子力學和編寫複雜代碼的系統，卻在最基礎的 OAuth 流程上栽了跟頭。這不是什麼深奧的算法危機，而是純粹的工程怠惰。攻擊者只需要引誘用戶點擊一個特製連結，就能透過預取機制把帳戶的 Session Token 像送外賣一樣送到攻擊者的伺服器上。這讓人不禁懷疑，Sam Altman 每天在推特上談論 AGI 的時候，是不是忘了家裡的門鎖其實只是用透明膠帶貼著的。

技術細節比表面看起來更驚悚。這個漏洞的核心在於 ChatGPT 處理第三方集成的邏輯缺陷。當你點擊一個看似無害的連結，ChatGPT 的預加載機制會主動去請求目標地址，並在 Header 中夾帶了不該出現的認證信息。這在現代 Web 開發中是極其低級的錯誤。我們在談論的是一個估值千億美元的公司，他們卻在處理跨站請求偽造（CSRF）和認證隔離上，表現得像個剛畢業的實習生。更別提那個桌面客戶端的「工作空間」功能，竟然能被遠程訪問本地文件系統。這已經不是功能缺陷了，這簡直是把用戶的電腦變成了一個公開的 FTP 伺服器，還順便幫駭客把權限提升到了管理員級別。

這種崩潰式的複雜度增長，是所有單體大模型應用的通病。當你不斷往一個聊天框裡塞進去代碼解釋器、文件系統訪問、聯網搜尋以及無數的第三方插件時，系統的攻擊面是呈指數級擴張的。OpenAI 顯然陷入了「功能競爭」的焦慮，為了讓 ChatGPT 看起來無所不能，他們犧牲了安全工程中最基本的「最小權限原則」。

相較於 Qwen3.8-27B 在特定基準測試中的表現，ChatGPT 在處理這類工程安全問題上的傲慢更值得警惕。在橫向對比中，你會發現四大平台對「安全」的定義截然不同。Claude 顯得極度保守，甚至有時候保守到讓人發火，你在對話中稍微涉及一點敏感路徑，它就會像個受驚的小貓一樣縮回去。而 Google 的 Gemini 則背靠著老牌搜尋巨頭的工程底蘊，雖然模型本身偶爾胡言亂語，但在底層架構的沙箱隔離上，確實比 OpenAI 穩健得多。至於 Grok，它還在忙著證明自己足夠「反覺醒」，安全機制對它來說可能更像是一種束縛。

每當 Qwen3.8-27B 這種模型被拉出來對標性能時，我們往往忽略了，在大模型真正落地成為生產力工具的過程中，決定勝負的往往不是模型參數，而是那幾百萬行用來包裹模型的工程代碼。OpenAI 的問題在於，他們試圖用一個「全能特工隊」來管理這一切，但現實卻是隨著代碼量的激增，系統的 Bug 表面積也在同步擴大。當一個系統大到沒有人能完全理解其內部組件如何相互作用時，安全就成了一種奢望。

我們現在正處於一個很尷尬的階段。一方面，我們被告知 AI 將接管世界上大部分的重複勞動，包括寫代碼和審計安全；另一方面，這些 AI 的締造者們甚至無法保護好自家產品的 Session Token。這算不算一種現代版的「醫者不自醫」？

如果我們必須在「全能但漏洞百出」的 ChatGPT 和「專才但相對封閉」的其他模型之間做選擇，這是否意味著我們已經默認了便利性永遠優先於隱私？當下一次你點開一個 ChatGPT 分享連結時，你是會期待看到一段精妙的代碼，還是會擔心這其實是通往你個人隱私的後門？既然連最基本的帳戶權限都能被一個連結騙走，那我們還有必要繼續討論 AI 什麼時候會產生意識嗎？畢竟在 AI 統治世界之前，人類的低級工程錯誤可能就已經把我們毀得差不多了。
