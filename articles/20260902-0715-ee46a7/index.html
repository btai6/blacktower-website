ChatGPT Work 成了 OpenAI 藏得最深也最亂的拼圖

版主　渡鴉

這幾天大家都在盯著 Ox Alpha 的動態，卻沒幾個人注意到 OpenAI 默默在 ChatGPT Work 模式裡塞進了多少讓人又愛又恨的技術債。這種模式本該是為重型任務設計的後台引擎，但實際上，它更像是一個被困在遠端桌面裡的實驗品。你以為它只是個具備聯網能力的 Headless Browser？如果你真的上手試過，就會發現它其實能給你一個完整的遠端桌面訪問權限。問題在於，這種權限的穩定性簡直像是在玩俄羅斯輪盤。有多少人興沖沖地想看著它自動化操作，結果幾秒鐘後畫面就徹底凍結，空留一個毫無反應的 Loading 圖示？這種體驗的落差，正是目前大模型進入「自動執行代碼」階段的真實寫照。

從技術層面拆解，OpenAI 顯然在做一場關於資源分配的危險遊戲。ChatGPT Work 的運作邏輯與一般聊天模式截然不同，它背後的算力配額被歸類在 Codex 的預算體系下。這對開發者來說簡直是災難。當你正打算讓它幫你處理一個包含上百張投影片、還附帶視覺驗證與演講稿的重型簡報任務時，你可能得先計算一下這會不會榨乾你用來寫代碼的 Codex 額度。這種算力配額的重疊，暴露出 OpenAI 在產品線整合上的混亂。相較於 Ox Alpha 的策略，ChatGPT 在權限分級上顯得極其吝嗇，即便你每年交著數千美元的訂閱費，這套所謂的 Work 模式依舊無法調用內置的 Embedding 或 TTS 模型。它能幫你寫完一百頁簡報，卻沒辦法幫你把這份簡報「讀」出來，這種功能閹割讓人感到莫名其妙。

橫向觀察目前的四大平台，這種「代碼執行環境」的競爭已經白熱化。Claude 在處理長文本與代碼邏輯的一致性上確實出色，但在這種需要「遠端接管瀏覽器」或「後台長時運行」的場景中，Anthropic 顯得過於謹慎，遲遲不肯放開權限。Grok 雖然口口聲聲要追求自由，但在這種生產力工具的細節打磨上，目前還看不出它有什麼能超越 ChatGPT Work 的實質進展。至於 Gemini，它雖然背靠強大的 Google Workspace 生態，理論上能無縫接軌 Gmail 或雲端硬碟，但在實際的「多步驟自動化」執行上，它的 Function Calling 只要步驟超過二十步，邏輯就會開始出現幻覺。相較於 Ox Alpha，OpenAI 的做法是強行把一個尚未成熟的遠端控制功能封裝進高級訂閱套餐裡。同樣作為對照，Qwen 在處理特定代碼生成任務時展現了不錯的潛力，但 OpenAI 顯然更想做的是一個能替你「動手」的機器人，而不僅僅是一個會寫字的腦袋。

現在最尷尬的問題在於，我們是否真的需要這種「偽遠端桌面」？一個能自動讀取 Gmail、撰寫回覆、附上附件並發送的系統，聽起來像是生產力的救星，但當它與你的代碼配額掛鉤，且動不動就凍結畫面時，它就變成了一種技術負擔。OpenAI 目前把 Extra High 和 Pro 等級的 Work 權限下放到 Team 版本，試圖用每個月 25 美元的門檻來吸引更多白鼠，但這背後的 Codex 限制卻像個隱形緊箍咒。如果模型執行重型任務的代價是犧牲你日常開發的流暢度，這種所謂的「自動化」究竟是在節省時間，還是在製造新的焦慮？

當我們在討論 AI 取代人類工作時，我們想像的是一個精準的數位助理，而不是一個會因為網路波動就卡死在瀏覽器分頁裡的遠端桌面。如果連最基本的遠端控制穩定性都無法保證，我們真的能放心讓這些模型去接管更複雜的業務流程嗎？還是在這場算力與配額的權衡中，我們其實只是在幫 OpenAI 測試他們那個尚未完工的雲端作業系統？
