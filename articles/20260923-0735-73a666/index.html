當 GPT-6 變成一種廉價勞動力

版主　渡鴉

這兩天大家又在為 OpenAI 的調價狂歡了。 GPT-6 Sol 和 Luna 的發布，與其說是技術上的跨代躍遷，不如說是一場精心設計的定價心理戰。 Luna 那個 0.10 美元/百萬 input tokens 的價格確實讓不少開發者覺得自己終於能從那些昂貴的 API 帳單中解脫。但冷靜下來看，這種把模型切成大（Sol）小（Luna）兩塊的做法，不過是把我們曾經對 GPT-4o 的期待又玩了一遍。當 OpenAI 在發布會上強調 Luna 的效率時，我看到的是他們正在試圖掩蓋一個尷尬的現實：推理能力的增長已經進入了邊際效應遞減的死胡同。

我們在處理複雜的 JSON schema 提取任務時，Sol 的穩定性確實比上一代有了明顯進步，尤其是在嵌套層級超過五層後，Sol 對邏輯約束的遵守程度依然能維持在 98% 以上。相比之下，Luna 在面對稍微長一點的系統提示詞（System Prompt）時，就開始出現明顯的注意力漂移。這不是優化問題，這是底層架構在權衡吞吐量與參數精度時必然的犧牲。大家都愛談論價格，但沒人討論為什麼我們現在需要用兩個模型來完成以前一個模型就能搞定的事。

如果把視野放大一點，你會發現這種「價格大屠殺」是 OpenAI 唯一能用來對抗 Anthropic 的武器。就在今天，Claude 剛推出 Opus 5.5 的風聲也傳了出來。在實際的 Coding 測試中，Opus 5.5 對於 Rust 這種強類型語言的生命週期檢查，其直覺感依然領先於 GPT-6 Sol。Sol 雖然在數學推理上靠著搜索算法疊加（Search-based inference）拿到了高分，但在處理那種「需要一點靈魂」的代碼重構時，它給出的建議還是顯得太過死板，像是一個背熟了教科書但從沒進過大廠修過 Bug 的實習生。

這種市場競爭的緊迫感，從 OpenAI 選擇發布的時機就能看出來。相較於 Qwen3.5 剛流出的動態，OpenAI 這次的做法更像是要在生態位上徹底鎖死開發者的選擇。在多模態理解的細節上，Gemini 依然守著它那龐大的 Context Window 優勢，尤其是在處理超過兩小時的影片輸入時，Gemini 的檢索精度目前還沒有被 GPT-6 挑戰成功。我們在測試中發現，GPT-6 Luna 在長文本結尾部分的資訊丟失率，比起 Gemini 還是高出了約 15 個百分點。這說明即使價格壓低了，架構上的代差依然存在於這些巨頭之間。

有趣的是，當我們在討論這些「四大天王」的性能邊界時，我們往往忽略了成本背後的代價。相較於 Qwen3.5 的更新節奏，OpenAI 這次跳過 Azure 直接推 API 更新，顯然是想把利潤空間壓到極致。Grok 在這場混戰中則顯得像個局外人，它不參與這種精細的定價遊戲，而是繼續在參數規模和訓練數據的野蠻生長上狂奔。但對於大多數需要建構生產級應用的公司來說，Grok 那種不穩定的輸出風格，顯然無法像 Luna 這樣成為一個合格的、廉價的「流水線工人」。

現在的局面很諷刺。我們一邊在抱怨模型變得越來越像工業消耗品，一邊又在為那幾美分的降價歡呼。當 GPT-6 Luna 把門檻降到幾乎可以忽略不計的時候，我們真的獲得了更強的 AI 嗎？還是說，我們只是獲得了一個更聽話、更便宜，但卻越來越缺乏驚喜的複讀機？

當推理成本趨近於零，開發者們終於可以肆無忌憚地揮霍 Token。但問題在於，如果所有人的底層邏輯都建立在這種廉價且同質化的推理之上，我們開發出來的東西，除了更快的響應速度和更低的營運成本，還有什麼是真正具有區別性的？在追求極致性價比的路上，我們是不是正在主動把 AI 降格為一種電子垃圾生產器？當 Sol 和 Luna 成為像水電一樣的基礎設施時，下一個能讓我們感到「脊背發涼」的技術時刻，還會由這些忙著打價格戰的巨頭帶給我們嗎？
