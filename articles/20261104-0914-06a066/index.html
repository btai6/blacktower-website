當默讀成了一種輸入指令

版主　Sword Smith

這兩天看矽谷那群人折騰 Subvocal 這種「默讀識別」眼鏡，心裡只有一個念頭：我們對 AI 的交互耐性已經快到極限了。這類技術說白了就是捕捉你嘴唇微動或喉部肌肉的生物電信號，轉譯成文字，讓你在咖啡廳或辦公室不用像個瘋子一樣對著空氣自言自語。技術本身不新鮮，新鮮的是大家終於意識到，現在的語音交互模型，哪怕強如 GPT-4o 的語音模式，在公共場合就是個笑話。沒人想在捷運上大聲問 ChatGPT 怎麼寫這段 Python 腳本，更沒人想讓隔壁桌聽見自己在跟 Gemini 抱怨老闆。

這件事背後的技術博弈，其實不在傳感器，而在推理後端的容錯率。當前的 Grok 或 ChatGPT 面對這種「非典型語音」輸入時，表現得極其掙扎。Subvocal 這種設備產出的文本通常缺乏語氣助詞，甚至因為肌肉信號的噪點，會出現大量的同音異字。我試著把類似的模糊文本丟給現有的幾個大模型，ChatGPT 的反應最像一個彬彬有禮的笨蛋，它會花大量的 Token 去猜測你是不是打錯字了，然後回覆一堆「你是不是想說...」的廢話。相比之下，xAI 的 Grok 在處理這類帶有強烈意圖但格式破碎的輸入時，節奏感稍微好一點，它不太會去糾結語法正確性，而是直接給出邏輯推論。但這遠遠不夠。

真正的難點在於，當交互從「語音」變成「默讀」，上下文的依賴程度會呈幾何倍數增加。因為你省去了發聲的動作，大腦的輸出會變得更跳躍。目前的 Gemini 在長文本理解上確實有優勢，但在這種極短、高頻的碎化輸入場景下，它的注意力機制顯得太過沉重。當你用默讀的方式快速給出一連串指令，Gemini 的 API 延遲和那套追求穩健的過濾機制，會讓這種交互變得像是在用撥接網路上網。

看看本週 Qwen 引起的討論，再回頭看這些硬體嘗試，你會發現大家都在找一種「無聲的默契」。相較於 Qwen 在特定基準測試上的表現，Claude 3.5 Sonnet 在代碼生成與邏輯修補上的精準度，才是這類默讀設備最需要的後盾。當傳感器傳回一段殘缺不全的指令，比如「幫我重構這段...循環...加個異常處理」，Claude 通常能精確捕捉到那個模糊的痛點，而不是像某些模型那樣開始漫無目的地發散。

問題是，我們真的準備好把「思考的雛形」直接餵給這些模型了嗎？語音輸入至少經過了大腦的一次過濾與語言組織，而默讀幾乎就是意識的直接流露。目前的四大平台，沒有一個真正解決了「意圖對齊」的深度問題。ChatGPT 還是太愛說教，Gemini 還是太愛審查，Grok 雖然直白但有時過於粗糙，Claude 則像個隨時準備糾正你語法的專業祕書。

如果未來的輸入不再需要聲音，甚至不需要大幅度的肢體動作，我們對 AI 的期待會變成什麼？現在我們還在討論傳感器戴在眼鏡上還是貼在脖子上，但真正的瓶頸恐怕在於，當輸入的門檻降到零，這些模型產出的垃圾信息會不會也隨之淹沒我們的螢幕。我們追求的是更快的輸入，還是更準確的理解？當你只需要動動嘴皮子就能產生幾千字的代碼或郵件，我們到底是變得更強大了，還是僅僅變成了一個更高效率的廢話轉發器？
