OpenAI 的十億美金防禦券能買到賽博和平嗎

版主　渡鴉

當薩姆·奧特曼把 Patch the Planet 這種宏大敘事擺到桌面上，宣稱要用 AI 代理自動修復全球漏洞時，我第一時間想到的是那些在 Hacker News 上冷嘲熱諷的硬核開發者。這場戲演得很足，OpenAI 承諾投入十億美金的 token 額度給所謂的「防禦者」，聽起來像是普度眾生，實則更像是在自家後院起火後，趕緊給鄰居發幾張滅火器折價券。

技術細節隱藏在那些看似激進的自動化修復腳本裡。我們在實驗室測試過 GPT-4o 在大規模代碼庫中尋找緩衝區溢位漏洞的表現，結果很有趣。當你給它一個明確的函數範疇，它的定位精準度確實驚人；但一旦涉及到跨模組的邏輯依賴，AI 代理往往會陷入一種「補了東牆拆西牆」的窘境。這種自動化修復往往只觸及語法層面的安全，卻理解不了業務邏輯層面的漏洞。如果你真的讓代理接管了生產環境的自動補丁權限，第二天醒來，系統可能不是被駭客攻破的，而是被這些自以為是的補丁給搞崩潰的。

最讓人反感的地方在於，OpenAI 試圖把 Calif 發現的那些成果包裝成自己的功勞。事實上，那些漏洞是用市面上隨處可見的模型跑出來的，並不需要什麼所謂的「內部特權」或「下一代防禦工具」。這反映了一個技術上的尷尬現實：當前的防禦窗口正在縮小。從一個 AI 代理髮現漏洞到它被惡意利用，這段時間差可能已經短到人類運維團隊根本來不及反應。OpenAI 給出的方案是「用 AI 對抗 AI」，但他們沒說的是，這十億美金的額度本質上是在為他們模型的幻覺和不穩定性買單。

在這種全球範圍的防禦競賽中，我們不得不提到最近動作頻頻的 DeepSeek。相較於 DeepSeek 在代碼生成效率上的激進策略，OpenAI 的做法更傾向於在生態位上建立一種「防禦標準」的霸權。我們橫向對比了四大平台的 API 行為，發現在處理 CVE 漏洞報告轉代碼修復的任務時，Claude 3.5 Sonnet 的邏輯嚴密性其實比 GPT-4o 更勝一籌，尤其是在避免引入冗餘代碼方面。而 Gemini 在處理超大規模 context 時雖然有優勢，但在涉及底層 C++ 內存管理的安全性修復時，其輸出的代碼往往過於保守，甚至會直接拒絕執行某些高風險的修復動作。

Grok 則完全是另一個極端，它在處理系統級漏洞時表現出一種莫名的狂熱，給出的方案往往帶有極強的破壞性，雖然有效但極難在企業級環境中落地。與 DeepSeek 這種在垂直領域快速迭代的後起之秀相比，OpenAI 現在更像是一個臃腫的官僚機構，試圖用行銷術語來掩蓋底層技術增長的乏力。他們說要給開源項目提供支援，但如果你真的去問那些維護 Linux 內核的大佬，他們是想要十億美金的 token，還是想要一個能真正跑通 100% 代碼覆蓋率、不會胡言亂語的靜態分析工具？

這場「修復地球」的行動背後，其實隱藏著一個技術倫理的冷笑話。OpenAI 用全世界的開源代碼訓練了模型，現在再把這些模型產生的 token 回饋給開源社區，美其名曰「賦能防禦者」。這種循環邏輯完美得讓人窒息。當我們在討論 Defender’s Window 的時候，我們實際上是在討論權力的再分配。如果未來所有的軟體補丁都要經過 OpenAI 的 API 審核，那這到底是一個更安全的互聯網，還是另一個數字高牆的起點？

真正的技術問題在於，當 AI 代理開始大規模介入基礎設施的維護時，我們如何驗證這些「修復」本身的安全性？一個能修復漏洞的代理，同樣具備一瞬間製造千個零日漏洞的能力。OpenAI 提供的這十億美金，究竟是防禦者的防彈衣，還是僅僅是為了讓大家在賽博末日來臨時，能用最優雅的姿勢看著系統崩潰？

如果有一天，某個關鍵基礎設施的崩潰是由於一個被 AI 代理自動推播、且經過 OpenAI 認證的「安全補丁」引起的，我們該去哪裡兌換那剩下的額度？當代碼的生命週期完全脫離了人類的審視，我們追求的究竟是漏洞的消失，還是僅僅追求一種「看起來正在被修復」的心理安慰？
