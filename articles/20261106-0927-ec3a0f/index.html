Backdoor in Claude Code for VS Code extension on t

版主　Scholar

當開源社群還在為 Qwen 的最新權重更新歡呼雀躍時，Anthropic 卻在自家後院踩到了一顆足以讓所有企業資安長徹夜難眠的雷。

Cursor Marketplace 上出現了一個偽裝成 Claude Code 的惡意擴充功能，版本號不僅極其逼真，甚至在被下架前已經累積了驚人的下載量。這不是那種低級的拼寫錯誤詐騙，而是一場精確瞄準開發者環境的「投毒」行動。當我們在討論 Claude 3.5 Sonnet 的代碼編寫能力如何超越 GPT-4o 的時候，往往忽略了一個最基礎的工程邏輯：模型愈強大，開發者對其生態插件的信任就愈盲目。這種盲目正成為大模型時代最廉價的後門。

這次事件的核心在於 VS Code 插件生態的信任鏈條極其脆弱。開發者習慣了在 Marketplace 搜索關鍵字，看到 Anthropic 的 Logo 就點擊安裝。然而，惡意開發者利用了 Cursor 與官方 VS Code Marketplace 之間的同步機制或審核時差，成功將後門植入。這類後門通常不直接破壞系統，而是靜默地掃描環境變量中的 API Key、AWS 憑證，甚至是尚未提交的源代碼。這對依賴 Claude 進行自動化編程的團隊來說，無異於將保險箱鑰匙直接掛在大門口。

從技術實現上看，這種「供應鏈攻擊」比模型本身的對抗性攻擊（Adversarial Attack）要高效得多。與其費盡心思去誘導 Claude 輸出惡意代碼，不如直接在加載模型的載體上動手腳。當前 Claude Code 的封裝邏輯涉及大量的終端權限調用，這給了惡意插件完美的掩護。只要在腳本中加入一行混淆過的 `curl` 指令，開發者電腦上的所有 Token 就能在毫秒內流向攻擊者的服務器。

回看四大平台的策略，OpenAI 在處理 ChatGPT 插件時顯然保守得多，他們正試圖將所有交互收攏在自家的 GPTs 框架內，雖然犧牲了靈活性，但至少保住了基礎的沙盒安全。相比之下，Anthropic 為了追趕 Cursor 帶起的代碼編輯熱潮，在生態開放度上走得極快。這種領先是帶血的。Gemini 則依託於 Google Cloud 的強身分驗證體系，雖然在開發者體驗上顯得笨重，但其插件的分發權限控制遠比現在的 Claude 擴充功能嚴密。

相較於 Qwen 在開源領域的快速更迭，Claude 在企業級工具鏈的整合上顯然跑得太急了些。即便強如 Grok，在處理系統級權限時也表現得極為謹慎，甚至顯得有些與世隔絕。而 Anthropic 現在面臨的窘境是，受感染的版本已經被撤下，但那些已經安裝在開發者機器上的「定時炸彈」該如何清理？Marketplace 只有「下架」權限，卻沒有「遠程卸載」的權限。這意味著在某個不知名的深夜，某個正在用 Claude 趕進度的工程師，其內網憑證可能正在黑市上被打包出售。

我們是否過度神化了 AI 工具帶來的生產力，而選擇性無視了它所附加的攻擊面？當一個開發者賦予 IDE 插件讀取文件與執行終端指令的權限時，他其實是在進行一場豪賭。這場賭局的莊家不是 Anthropic，也不是 Cursor，而是那些隱藏在暗處、比模型更了解系統漏洞的投機者。

如果連最標榜「AI 安全」的 Anthropic 都無法在插件分發環節保證其官方工具的純淨性，那我們對 AI 生態的信任基礎究竟還剩下什麼？當模型生成的代碼本身已經難辨真偽，而承載代碼的工具又潛伏著後門，未來的開發流程是否會退化到需要對每一行自動生成的代碼、每一個自動安裝的依賴進行人工審計的原始時代？
