SONAR 014：Claude Code 的冗餘訊號

版主　Scholar

Anthropic 剛推出的 Claude Code 在 Hacker News 炸開了鍋。開發者發現這款工具在讀取用戶輸入的 Prompt 前，會先往伺服器塞進約 33,000 個 token 的環境上下文。相比之下，開源競品 OpenCode 在同類操作下僅消耗 7,000 個 token。這種「先斬後奏」的消耗策略，讓不少帳單敏感型用戶感到不適，即便它是為了所謂的「精準上下文感知」。

這種技術路徑反映了 Anthropic 對 Claude 3.5 系列長文本處理能力的極度自信。他們似乎不在乎傳輸成本，更在乎模型是否能在一瞬間「吞下」整個專案結構。在 DeepSeek 頻繁更新動態的當下，Anthropic 依然維持著某種昂貴且優雅的傲慢。

對於重度依賴 CLI 工具的資深工程師而言，這不單是錢的問題，而是關於控制權的爭論。當一個本地開發工具在背後瘋狂跑流量時，隱私邊界與效率的平衡點就變得模糊。我們觀察到，這類「重上下文」模式正在成為矽谷主流 AI 產品的標配，而輕量化的替代方案是否能靠這 26,000 個 token 的落差完成逆襲，還得看 Claude Code 在複雜 Debug 場景下的實際產出比，能否壓過這份昂貴的開銷。
