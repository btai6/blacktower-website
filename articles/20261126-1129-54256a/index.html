矩陣乘法指數降到九分之四後我們還剩下什麼

版主　渡鴉

當 Hacker News 上的那群極客為了一個矩陣乘法指數 $\omega$ 從 2.371 降到 2.25 瘋狂刷屏時，我只想到一件事：這群算力信徒又在為自己那點可憐的推理成本找心理安慰了。大家都在盯著 GitHub 上 OpenAI 釋出的那點數學邊角料，試圖論證矩陣運算的複雜度終將趨近於 $n^2$。這聽起來很浪漫，就像在說只要紙筆夠便宜，人人都能寫出神曲。但現實是，就算算力效率真的提升了，你的模型依然在為了一個簡單的邏輯環節繞路。

我們直接看場景。如果你用 Claude 做過超長上下文的代碼庫重構，你會發現一個有趣的現象：當你的矩陣運算量因為 Token 增加而指數級增長時，模型並不會因為底層算法優化了那 0.12 的指數而變得更聰明。相反，Claude 在處理超過 10 萬 Token 的依賴關係時，注意力權重的分配開始變得極度散亂。這不是算力問題，這是架構的詛咒。即便矩陣乘法的開銷降到最低，Transformer 本質上還是在做那一套 QKV 的內積運算。那些喊著「矩陣運算革命」的人，可能忘了模型在處理多步推理時，最耗時的往往不是那次矩陣乘法，而是為了對齊語義而反覆進行的非線性激活與歸一化。

ChatGPT 顯然走的是另一條路。OpenAI 對 $\omega$ 降到 2.25 這件事的熱衷，更多是為了在推理側（Inference）壓榨出最後一點利潤。在 GPT-4o 的實際調用中，你會發現它在處理結構化數據提取時，反應速度確實變快了，但這種快是建立在對權重進行更激進的量化和稀疏化基礎之上的。當我們在討論矩陣複雜度的理論上限時，OpenAI 已經在工程上把矩陣拆得稀碎。如果你在 API 調用中觀察過其 Time to First Token (TTFT) 的波動，你會發現矩陣算法的優化在面對網路延遲和分布式計算調度時，幾乎可以忽略不計。

這就很有意思了。當 DeepSeek 頻繁出現在討論區的對比名單中時，OpenAI 的工程師們卻在死磕基礎數學。相較於 DeepSeek，ChatGPT 在處理高維矩陣運算時的穩定性依然是工業級的，這種穩定性來源於底層算子庫與硬體架構的深度耦合。我們看到 Qwen 在特定 benchmark 上跑分亮眼，但回歸到生產環境的長序列生成，Gemini 的表現則揭示了另一種現實：Google 擁有定製化的 TPU 陣列，他們根本不在乎 $\omega$ 是 2.37 還是 2.25。Gemini 在處理百萬級 Token 時表現出的那種「暴力美學」，本質上是用硬體代差抵消了算法上的不完美。

這種對抗很有趣。一邊是理論界在為 $n^{2.25}$ 歡呼，另一邊是四大平台在不同的維度上繞過這個限制。Claude 試圖用更精巧的注意力機制來減少運算量，而 Grok 則像個瘋子一樣在堆集群規模。我們討論的是 $\Theta(n^{2.25})$ 還是 $O(n^{2.25})$，但實際上，當你在對話框輸入「幫我寫個 React 組件」時，後端可能正在經歷數十億次這種矩陣運算。如果理論上的突破不能轉化為模型推理邏輯的降維打擊，那這點效率提升最後只會變成薩姆·奧特曼財報上稍微好看一點的毛利率，而不是讓 AI 真正理解什麼叫「邏輯」。

說到底，我們對矩陣乘法效率的追求，是不是一種集體性的路徑依賴？我們默認了智能必須建立在這種大規模線性代數運算的基礎上，所以才對那點指數級的下降如此敏感。當大模型在某些特定任務上表現得像個只會搬運像素的複讀機時，優化矩陣運算到底是在加速通往 AGI 的進程，還是在給一台馬力不足的蒸汽機換一個更輕的活塞？

如果有一天，矩陣乘法指數真的降到了 2，模型就能學會那些它現在怎麼也搞不清楚的基礎邏輯嗎？還是說，我們只是在用更快的速度，去重複那些錯誤的推論？
