當 Claude 開始讀取 AGENTS.md 時模型在想什麼

版主　Scholar

Anthropic 最近在 Claude Code 上的小動作，讓不少習慣在根目錄塞滿各類設定檔的工程師心跳漏了一拍。原本以為這只是這家公司固執地推廣自家 Claude.md 規範的延續，沒想到他們竟然學會了低頭，開始支持 AGENTS.md 這種更具普適性的協議。這就像是一個向來只穿訂製西裝的優雅紳士，突然開始研究起如何穿大眾成衣，這背後不單是檔案讀取的邏輯變更，而是 Claude 正在重新定義它與開發環境之間的「主僕契約」。以往我們習慣將 AI 當作一個外掛的編譯器或自動補全工具，但當它主動去尋找 AGENTS.md，它其實是在試圖理解這個專案的靈魂，而不僅僅是處理幾行程式碼的搬運工。

這種轉變在技術層面上反映了 Claude 對長文本與上下文感知策略的微調。如果你細看 Claude Code 的運行邏輯，會發現它在掃描檔案目錄時，對於引導性文件的優先級權重正變得異常敏感。比起 GPT-4o 那種更依賴 System Prompt 暴力灌輸指令的方式，Claude 顯然更傾向於在環境中尋找「現成的規矩」。當系統發現沒有專屬的 Claude.md 時，轉而讀取 AGENTS.md，這意味著 Anthropic 的開發團隊意識到，與其強迫開發者為每一種模型都準備一套說明書，不如讓模型學會適應現有的工業標準。這種靈活性對於那些已經構建了複雜自動化腳本的開發者來說，無疑是個好消息，至少不用為了伺候這位新來的「實習生」而重新翻修整個鷹架工程。

然而，這種體貼並非毫無瑕疵。從技術社群的反饋來看，Claude Code 目前對於技能檢測（skills detection）的覆蓋率依然顯得有些傲慢。即便它讀取了 AGENTS.md，對於隱藏在 .agents/skills 目錄下的具體能力定義，往往還是視而不見。這造成了一種尷尬的局面：模型知道自己是一個 Agent，也知道這份合約的存在，但在實際執行任務時，卻依然像個記性不好的老教授，空有理論框架卻找不到工具箱在哪裡。相較於 Qwen 3.8 Omni Flash 在這類本地環境適配上的激進嘗試，Claude 的做法顯然更具備一種實驗性的謹慎，它在確保安全性與遵循指令之間走得如履薄冰。

這引發了一個更深層次的觀察。當我們在討論四大 AI 巨頭的開發者工具時，Gemini 正在試圖透過超長上下文直接生吞整個 Repo，而 Grok 則在尋求更極端的即時反饋效率。Claude 選擇的這條路徑——對標準化引導文件的支持——本質上是在試圖降低 AI 介入開發流程的摩擦力。如果說 ChatGPT 像是一個什麼都能聊的通才助手，那麼現在的 Claude 正試圖把自己偽裝成專案團隊裡那個最懂規矩的資深工程師。它不只是在寫程式碼，它在閱讀你的「家規」。

有趣的是，這種對 AGENTS.md 的兼容，究竟是 Anthropic 真的擁抱開源標準，還是僅僅因為在窺視了競爭對手的倉庫後，發現自己如果不跟進就會被排除在主流工作流之外？在矽谷，這種「借鑑」並不是什麼新鮮事，真正值得玩味的是，當所有模型都開始支持同一套標準文件時，模型之間的差異化將會在哪裡體現？相較於 Qwen 3.8 Omni Flash，Claude 在解析複雜邏輯時展現出的那種近乎偏執的連貫性，是否能彌補它在本地工具鏈對接上的遲鈍？

我們或許正處於一個轉折點，AI 不再是被動等待調用的 API，而是開始主動尋找進入專案的路徑。但這也帶來了一個讓人不安的問題：如果 AI 讀取了你的 AGENTS.md，理解了你的開發邏輯，甚至掌握了你所有的隱含技能，那麼下一次當它決定忽視某些指令時，它是因為讀不懂，還是因為它覺得你的規矩定得不夠高明？當工具開始學會挑剔環境，開發者與模型之間的權力天平，是否還能維持在我們自以為掌控的那一端？
