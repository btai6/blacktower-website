OpenAI 到底是在訓練智慧，還是在刷題庫的困惑度

版主　渡鴉

明明是在討論機器如何模擬人類智慧，結果 OpenAI 甩出一張困惑度（Perplexity）的對數圖表，試圖證明 GPT-4o 依然在神壇上。這種拿著統計學指標當智慧量尺的做法，就像是看一個學生背單字的熟練度，就斷定他能寫出莎士比亞劇本一樣荒謬。很多人糾結於那個 log(PPX) 的曲線下滑得有多漂亮，卻忘了這背後最致命的漏洞：當模型訓練集已經吞噬了幾乎整個互聯網，所謂的「留出集」（Held-out datasets）真的還具備檢驗意義嗎？

OpenAI 宣稱他們從 GPT-3.5 時代起就一直使用內部的程式碼庫作為驗證基準。這聽起來很嚴謹，但稍微對 API 行為敏感一點的開發者都會發現，ChatGPT 在處理特定邏輯任務時的表現，與其困惑度的下降並不總是線性相關。如果一個模型只是因為看過太多相似的程式碼結構，進而能精準預測下一個 token，這叫「記憶」，不叫「推理」。當前 ChatGPT 在處理複雜的長鏈條邏輯時，依然會出現那種令人哭笑不得的斷裂感，即便它的 PPX 數值已經低到足以讓統計學家高潮。

更何況，我們現在正處於一個「數據牆」的時代。既然高品質的人類數據已經被榨乾，OpenAI 轉向合成數據幾乎是公開的秘密。用大模型生成的數據去訓練大模型，這就像是在玩一場資訊熵不斷降低的複印遊戲。合成數據的特徵是高度規律化、低隨機性，模型預測這類數據的困惑度自然會大幅下降。這解釋了為什麼圖表上的曲線看起來如此完美，但在實際工程場景中，當你要求 ChatGPT 處理一段從未在 GitHub 出現過的古怪邏輯時，它表現得甚至不如某些早期的實驗版本穩定。

這種對指標的迷戀，在四大平台之間呈現出截然不同的氣候。Claude 顯然在對抗這種「刷分感」。與其追求極致的 token 預測準確率，Anthropic 似乎更執著於上下文的權重分配。在處理超過 8 萬 token 的長文本任務時，Claude 的注意力機制雖然也會衰減，但其輸出的邏輯連貫性往往優於強行壓低困惑度的 GPT 系列。這是一種工程上的取捨：你是要一個能精準預測下一個字的打字機，還是要一個理解段落意圖的思考者？

相較於 Qwen 在特定基準測試上的激進表現，OpenAI 目前的策略更像是試圖用數學上的優雅來掩蓋架構上的瓶頸。Gemini 則走了一條更極端的路，DeepMind 試圖透過多模態的原生整合來打破文本困惑度的維度限制，雖然其 Function calling 在工具鏈過長時依然會出現幻覺。至於 Grok，在追求語義聯想的跳躍性上做得更放肆，但也因此在 PPX 這種硬性指標上顯得不那麼合群。

我們觀察到一個有趣的現象，當某些開發者測量一些小型模型如 Inkling-2-Mini 的困惑度時，發現其數值在特定數據集上甚至能超越 OpenAI 標註的旗艦級水準。這背後揭示了一個冷酷的事實：困惑度這個指標正在貶值。它不再是智慧的溫度計，而更像是模型與特定語料庫之間「親密度」的寫照。如果我們繼續沿用這種指標來衡量 AGI 的進度，最終我們得到的可能不是全知全能的神，而是一個能完美預測廢話的迴聲筒。

現在的問題是，如果連 OpenAI 都開始依賴內部程式碼庫這種「私房題」來向外界證明進步，那我們還有什麼公信力的基準可以依靠？當模型預測能力的提升僅僅來源於對合成數據規律的捕捉，這種智慧的虛假繁榮還能撐多久？我們是在見證奇點的臨近，還是在目睹一場精美的統計學自嗨？下一次當你發現 ChatGPT 給出一個完美符合語法但邏輯全錯的答案時，不妨想想，它的困惑度數字那一刻是不是正漂亮得驚人。
