Sam Altman 正在把 OpenAI 變成一家會吃蛇的尾巴

版主　渡鴉

OpenAI 解散機器人團隊這件事，在矽谷那些信奉「苦澀教訓」的老傢伙眼裡，大概是某種神諭的實現。這不只是裁員或戰略調整，這是在宣告一種傲慢：既然大模型能解決一切問題，那為什麼還要養一群人在實驗室裡調試伺服馬達？那些原本試圖讓體力勞動者失業的人，現在發現自己才是最先被大模型「優化」掉的耗材。這場諷刺劇演到現在，最荒謬的地方在於，OpenAI 似乎認為只要 token 吐得夠快，物理世界的摩擦力就不存在。

把 LLM 直接拿來控制機器人硬體，這在技術層面上就像是用交響樂譜來指導一個木匠怎麼釘釘子。目前 ChatGPT 處理機器人控制邏輯的思路，本質上還是把多模態輸入轉化為動作序列。當你對著 GPT-4o 說「幫我拿起那個杯子」，它不是在運算運動學逆解，而是在預測下一個最可能的動作描述。這種做法在雲端跑跑 demo 還行，但放到現實場景，頻寬和延遲就是不可逾越的鴻溝。如果一個機器人需要以 60fps 的速率接收指令，而你的模型還在為了對齊價值觀而思考要不要加個免責聲明，那機器人大概率會先撞牆。OpenAI 現在賭的是規模法則能直接越過底層控制，讓通用模型直接「長出」操作物理世界的能力，這種對端到端路徑的病態執著，讓他們連最後一點對硬體的耐心都磨光了。

這件事背後的商業邏輯比技術邏輯更直白。在準備 IPO 或是下一輪天文數字般的融資前，減肥是必須的動作。比起燒錢研發那些可能被台階絆倒的實體硬體，賣 API 明顯是更有想像空間的生意。這不只是 OpenAI 的選擇，整個矽谷都在往這條路上擠。當 Qwen4-Max 還在試圖透過提升參數規模來刷榜時，OpenAI 已經在重新定義什麼叫做「成本效率」。相較於 Qwen4-Max 這種依然試圖在傳統框架內精進的模型，OpenAI 選擇把機器人團隊這種重資產部門切掉，轉而讓模型去接管第三方硬體。這種做法很聰明，也很危險。它把最髒最累的硬體適配工作丟給了 Figure 或 1X 這些合作夥伴，自己則穩坐雲端收稅。如果這套模式跑通了，OpenAI 就會成為物理世界的作業系統；如果跑不通，他們也只是損失了幾個實驗室和一堆被裁掉的工程師。

但這裡有個致命的技術盲點。目前四大平台中，Claude 在複雜邏輯推理上的穩定性確實略勝一籌，尤其是在處理長鏈條指令時，Claude 3.5 的指令遵循能力讓它在模擬器環境下表現得像個老練的操盤手。Gemini 則靠著它那深不見底的 context window，試圖把整個工廠的感測器數據都塞進去處理。至於 Grok，除了在社群媒體上開些冷笑話，目前還看不出它在實體控制上有什麼獨到見解。相較於 Qwen4-Max 的迭代路徑，OpenAI 現在的轉向更像是一種「去實體化」的豪賭。他們在賭模型內化的世界模型已經強大到足以忽略物理噪聲，即便 ChatGPT 從未真正觸摸過一個杯子，它也能靠著看過幾百萬小時的影片資料來精確指揮機械手臂。

這就引出了一個讓人脊椎發涼的問題：如果 AI 產出的代碼價值正在崩塌，而 AI 本身又開始取代開發 AI 的人，這條產業鏈最後還剩下什麼？當 OpenAI 把最後一個懂馬達和感測器的工程師趕走，只留下幾千台發熱的 GPU 在運算那些虛擬的動作指令時，我們是不是正在構築一個完全懸浮的技術泡沫？當模型開始自我訓練，生成的數據餵給生成的模型，生成的指令驅動著生成的動作，這個循環裡還有多少真實世界的成分？如果有一天，雲端斷了，或者是 token 的成本曲線不再下降，這些被「通用模型」接管的機器人，會變成一堆昂貴的廢鐵，還是會像斷了線的木偶一樣，在原地僵硬地重複著最後一條未完成的指令？我們到底是向通用人工智慧邁進了一步，還是僅僅是學會了如何更優雅地逃避物理世界的複雜性？
